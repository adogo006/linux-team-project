# 1. 로그인

## 입력

- 둘 중 하나라도 입력치 않았다면  
  "아이디와 비밀번호를 제대로 입력해라" (빨간 글씨)

```
API << 아이디, 비밀번호
해당 아이디, 비밀번호 DB에서 찾음
일치하지 않는 경우 : 오류 반환
일치하는 경우 : 해당 JWT 토큰값을 반환
API >> 토큰값
```

# 2. 회원가입

## 닉네임

- 한글, 영어, 숫자 (2~12자)  
  예외 처리 (실시간 확인)  
  예외 처리해야 중복 확인 버튼 가능 (글씨만 파란색)

```
API << 닉네임
중복확인
API >> 중복 여부(T,F)
```

- 버튼 변환 (파란색 체크 표시 + 테두리)
- 다시 수정할 경우  
  처음부터 다시 예외 처리 (실시간 확인)  
  버튼 검은색으로 되돌리기

## 아이디

- 영문, 숫자 (2~12자)

```
닉네임과 동일 (API 입출력 포함)
```

## 비밀번호

- 영문, 숫자, 특수문자(8~자)  
  실시간 확인
- 재입력 동일

## 회원가입 완료 버튼

- 닉네임 중복 확인  
  아이디 중복 확인  
  비밀번호 양식 준수  
  재입력 동일
- 전부 해당해야 버튼 명료화.

```
API << 닉네임, 아이디, 비밀번호
새로운 사용자 생성
```

- DB에 정보 추가와 동시에 로그인 세션으로 복귀

## 예외

- 정말 드물지만 다음과 같은 경우가 있을 수 있다 :
  사용자 A와 B가 동시에 같은 아이디로 중복한 경우...  
  고유 토큰이 존재한다고 생각하고... 비밀번호까지 겹쳐야하는...  
  생각 안해도 될 것 같다!

# 3. 홈

## 프로젝트 나열

- `사용자`에 따른 `참가하고 있는 프로젝트``들`과 `생성자`를 표기해야함

```
API << 토큰
API >> 참가하고 있는 [프로젝트 ID, 프로젝트 명, 생성자]를 전부 반환.
```

- `프로젝트 명`, `생성자`를 프론트에 보여주고  
  프로젝트를 누른다면 `프로젝트 ID`를 `editor.html`로 반환

## 프로젝트 추가

- `생성자`가 `사용자`인 `프로젝트`를 DB에 추가

```
API << 프로젝트명, 토큰
DB에 프로젝트 추가
부여된 프로젝트 ID를 사용자-프로젝트ID에 추가
```

- `프로젝트 명`, `생성자` = 나 : 프로젝트 나열을 실행.  
  프로젝트를 누른다면 `프로젝트 ID`를 `editor.html`로 반환

## 초대 목록

- `사용자`에 따른 `초대한 사람 목록`, 그에 따른 `프로젝트 명`을 보여줘야함.  
  `수락` 혹은 `거절`할 수 있음

```
API << 토큰
API >> 초대한 사람 목록, 그에 따른 프로젝트 명, 프로젝트 ID
```

- `수락` : `타 사용자`가 `생성자`인 `프로젝트`를 나열란에 추가

```
API << 토큰, 초대한 사람 목록, 프로젝트 ID
DB: 사용자-프로젝트 ID 추가
사용자-초대한 사람 목록 / 사용자-초대한 사람 목록- 프로젝트 ID 에서 해당 사항 제거
```

- 프로젝트 추가 후 `프로젝트 나열`를 실행
- 초대한 사람을 `초대 목록`에서 삭제

- `거절` :

```
API << 토큰, 초대한 사람 목록, 프로젝트 ID
DB : 사용자-초대한 사람 목록 / 사용자-초대한 사람 목록- 프로젝트 ID 에서 해당 사항 제거
```

- 초대한 사람을 `초대 목록`에서 삭제

## 폴더, 파일 목록 나열

- `프로젝트 ID`를 기반으로 `폴더, 파일 이름`을 나열
- 트리구조 형식

```
API << 프로젝트 ID
API >> 프로젝트 폴더, 파일의 이름 나열
```

## 폴더, 파일 추가

- 전체에서 폴더, 파일을 추가하는 것.
- 있는 폴더 내부에 폴더, 파일을 추가하는 것.

```
API << 폴더 또는 파일의 이름 / 폴더인지 파일인지
DB에 저장
API >> 새롭게 폴더, 파일 목록 나열
```

## 사용자 나열

- 본인이 생성자라면 : 가장 위에 생성자 및 본인인 자신을, 그 밑으로 멤버 가나다 순 나열
- 본인이 멤버라면 : 가장 위에 본인을 (나)표시로, 그 아래에 프로젝트장, 그리고 그 밑으로 멤버 가나다 순 나열

```
API << 프로젝트 ID
API >> 생성자 이름, 사용자들 이름
```

## 사용자 초대

- 본인이 `생성자`라면, 멤버를 초대할 수 있음
- 본인 `토큰`이 `생성자`인지 확인하고 버튼이 떠야함.

```
API << 프로젝트 ID, 초대할 사용자 ID
초대할 사용자에게 초대장을 보냄. DB에서 초대한 사람 목록쪽에 추가해야함.
```

- 초대 후, 초대 창 닫힘 (프론트 JS)

## 사용자 추방

- 본인이 `생성자`라면, 멤버를 초대할 수 있음
- 본인 `토큰`이 `생성자`인지 확인하고 버튼이 떠야함.

```
API << 프로젝트 ID, 해당 멤버 ID
DB에서 제거
API >> 갱신된 사용자 목록
```

- 다시 사용자 나열.

## 코드

- 선택한 파일에 맞는 코드를 불러오기.

```
API << 프로젝트 ID, 파일 ID
API >> 코드
```

## 수정 로그

- 수정을 진행하다가, 수정 버튼을 다시 누르는 경우 수정 종료  
  이때 수정 로그가 남게 됨.

- 깃허브식 구현 -> 누가 / 언제 / 무엇을 : 추가된 부분, 삭제된 부분 :: 너무 많다면 생략

```
API << 프로젝트 ID, 파일 ID
API >> 기존에 저장되어있던 코드
```

- 프론트에서 기존의 코드, 수정된 코드를 깃허브식으로 비교

```
API << 프로젝트 ID, 파일 ID, 수정한 사용자 토큰, 수정된 내역
DB에 저장
```

- 수정로그에 보여주기. (누가 언제 무엇을)
